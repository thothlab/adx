# ADX — Android Device eXplorer

Доступ к файлам Android-устройства по USB через MTP. macOS, Windows, Linux.

Аналог Android File Transfer, у которого три заявленных отличия — и все три проверяемые:

1. Долгая передача не замораживает интерфейс: чтение идёт окнами, освобождая единственную
   сессию MTP между ними. **Сделано и измерено** — см. ниже.
2. Устройство, захваченное чужим процессом, названо поимённо, а не спрятано за «устройство
   недоступно». **Сделано**; освобождение из интерфейса в MVP не вошло — после прогона
   выяснилось, что на macOS `ptpcamerad` режим MTP не перехватывает.
3. Сессия переживает сон компьютера, блокировку экрана и перевтыкание кабеля.
   **Сделано наполовину:** перевтыкание кабеля приложение переживает само - оно проверяет
   связь после каждого затишья на шине и переоткрывает мёртвую сессию, а «Обновить» теперь
   означает «переподключиться». Сон компьютера так не проверялся: там устройство может
   вернуться иначе, и это оставшийся долг.

**Статус: 1.0.4, работает на живом устройстве.** Проверено на vivo Y31 под macOS:
список подключённых устройств, выбор накопителя, дерево папок и содержимое, запись файлов
и папок на устройство (в том числе перетаскиванием из Finder), удаление, переименование,
создание папок. Сборки под Windows и Linux собираются, но их никто не запускал.

Скачивание на компьютер прогнано на vivo Y31: дерево из четырёх файлов на трёх уровнях
скачивается побайтно тем же, 31.5 МБ/с, и **во время передачи прошло четыре листинга папок,
худшее ожидание 317 мс** — то есть сессия действительно отпускается между окнами чтения.
Отмена срабатывает внутри файла за 0.2 с и не оставляет недописанного.

Превью масштабируется кнопками, клавишами и щипком: картинки - по-настоящему,
PDF - трансформацией, потому что встроенный просмотрщик движка своего масштаба
не отдаёт (проверены размер элемента, `#zoom=` в URL и css-свойство `zoom`).

Превью файла по двойному клику прогнано на vivo Y31: картинка, PDF на 400 КБ,
видео на 1.0 ГБ (первый кадр меньше чем за 8 секунд) и аудио `.m4a`. Видео и
аудио идут потоком через схему `adx://` с диапазонами байт, а не читаются в
память. Текстовое превью написано и покрыто тестами, но на устройстве не
открывалось.

Список файлов рисует только видимые строки, поэтому папка на 5000 объектов
листается без задержки. Клик по заголовку колонки сортирует по имени, размеру
или дате, повторный клик разворачивает порядок. Проверено на синтетических
данных в самом приложении (WKWebView): последняя строка достижима, вход в папку
с конца длинного списка показывает её содержимое сверху, сортировка переживает
перечитывание папки и не теряет выделенную строку. На устройстве с настоящей
папкой такого размера не мерялось - там к отрисовке добавляется чтение листинга
по USB.

## Установка

Готовые сборки — во [вкладке Releases](https://github.com/thothlab/adx/releases).

**Сборки не подписаны:** сертификата у проекта пока нет.

- macOS: `xattr -dr com.apple.quarantine /Applications/ADX.app` либо правый клик → «Открыть».
- Windows: SmartScreen → «Подробнее» → «Выполнить в любом случае».

На телефоне нужно выбрать режим передачи файлов (MTP). Обойти это со стороны компьютера
нельзя: какие USB-интерфейсы показать, решает само устройство, и пока MTP-интерфейса нет,
обращаться просто не к чему. Android умеет запомнить выбор — в настройках есть режим USB
по умолчанию.

## Разработка

```bash
pnpm install
pnpm tauri:dev      # окно приложения
pnpm typecheck && pnpm lint && pnpm test
cargo test --workspace
```

Диагностика на подключённом устройстве — три примера, идущие тем же кодом, что и приложение:

```bash
cargo run -p adx-mtp --example probe       # что видно, открывается ли сессия, что в корне
cargo run -p adx-mtp --example ls DCIM     # чтение папки по пути
cargo run -p adx-mtp --example roundtrip   # сквозная проверка записи (создаёт и убирает ADX-selftest)
cargo run -p adx-mtp --example download    # сквозная проверка чтения (создаёт и убирает ADX-selftest-dl)
```

`download` проверяет то, чего не проверит ни один unit-тест: совпадает ли скачанное с
исходным побайтно, воспроизводится ли вложенность, отменяется ли передача внутри файла — и
главное, отвечает ли устройство на листинг, пока с него идёт крупный файл. Последнее верно
только потому, что сессия отпускается между окнами чтения; пример это измеряет и валит
прогон, если ожидание листинга выросло.

Релиз собирается пушем тега `v*`: GitHub Actions делает установщики под три системы
и выкладывает их в Releases.

Dev-сервер слушает **1430/1431**, а не дефолтные для Tauri 1420/1421: на той же машине
на дефолтной паре живёт Pane, и при `strictPort` пересечение валит `tauri dev`.
Порт задаётся в двух местах — `vite.config.ts` и `devUrl` в `src-tauri/tauri.conf.json`.

## Устройство репозитория

```
src/                  SolidJS: компоненты, сторы, i18n, стили
src-tauri/            команды и события Tauri, точка входа
crates/adx-core/      модель, состояния, ошибки — без Tauri и без MTP
crates/adx-mtp/       единственный крейт, который знает про mtp-rs
```

Два правила, которые проверяются, а не подразумеваются:

- **Вне `crates/adx-mtp` нет упоминаний `mtp_rs::`.** Библиотека молодая (0.30.0), версия
  пинуется точно; смена бэкенда не должна доходить до UI.
- **Фоновые задачи — только через `tauri::async_runtime::spawn`.** `tokio::spawn` в `setup()`
  Tauri роняет macOS-сборку с SIGABRT ещё до появления окна.

Нативные диалоги (`confirm`, `prompt`, `alert`) мертвы в Tauri WKWebView — запрещены правилом eslint.

## Известные ограничения по платформам

**macOS.** Ходовое утверждение, что системный агент `ptpcamerad` перехватывает
Android-устройства и мешает работать, **для режима MTP не подтвердилось**: на Darwin 25.5
сессия открывается с первой попытки при работающем агенте. Перехват относится к PTP.
Замерено, а не пересказано — см. `cargo run -p adx-mtp --example probe`.

Устройство всё же может держать другое приложение (например запущенный Android File
Transfer). ADX показывает это отдельным состоянием и называет процесс поимённо. Прав
администратора для освобождения не требуется: агент живёт в пользовательском домене
`gui/$UID`.

Отдельно: `adb` держит USB-узел устройства, и MTP при этом открывается нормально — они
занимают разные интерфейсы. Имя владельца узла само по себе не означает, что устройство
недоступно.

**Windows.** Работает через нативный WPD, установка драйверов и Zadig не нужны.

**Linux.** Нужны udev-правила для доступа к USB без root — файл `99-adx.rules` и шаг установки
появятся вместе с упаковкой.
